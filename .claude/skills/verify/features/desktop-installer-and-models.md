# Local Installer, Desktop client, Local Models, and BYOK

The Local Client surface lets a user launch Linger's loopback installation manager in a private home, select an AI runtime or Bring Your Own Key (BYOK) endpoint, validate BYOK endpoints safely against SSRF, run the Electron Desktop client with bundled Local Computer daemon and resume/upgrade flows, and manage local model downloads and model sources in Settings -> Models.

## Sub-features

- `installer-private-auth` creates `installer/launch.html` with POSIX `0700`/`0600` permissions, rejects missing-`Origin` `POST /api/session` with HTTP `403`, issues an `HttpOnly; SameSite=Strict` browser session cookie, and rejects one-time token replay with HTTP `401`.
- `installer-ui-and-byok-ssrf` renders the Local Installer React SPA (`Choose your harness`, `Installation plan` radiogroup), opens the `BYOK` configuration form (`Base URL`, `Path`, `Endpoint`, `API key`, `Model`, `List models`, `Test`), and refuses a link-local metadata address (`http://169.254.169.254/latest`) with HTTP `400 BYOK_INVALID_CONFIG` and visible `Couldn't connect` toast.
- `installer-clean-stop` shuts down an owned installer instance cleanly via `SIGTERM` and `installer.js --home <tmp> --instance <name> --stop` with exit code `0`.
- `local-client-host-suites` verifies deterministic contracts across `@linger/service-kit` BYOK rules, `@linger/local-installation`, `@linger/linger-installer`, `@linger/desktop`, Python Desktop packaging scripts, and Go Daemon `localmodels` / `model_source` packages.
- `desktop-gui-and-models-surface` covers Electron Quick Install / Connect to Server, upgrade from the previous release, sleep/wake/crash/quit resilience, and Web Settings -> Models (`/t/:tenantId/settings/models`) local model download/load/unload/BYOK switching on target OS hosts.

## How to get to it (user POV)

- Run the standalone Local Installer (`node apps/linger-installer/dist/installer.js --home <private-dir> --source-repo <repo> --instance <name> --no-open --port 0`) and open the loopback URL written to `<private-dir>/installer/launch.html` in a browser.
- Launch Linger Desktop from source (`pnpm --filter @linger/desktop start`, with isolated `LINGER_DESKTOP_USER_DATA` and `LINGER_HOME`) or from a packaged `.dmg` / `.tar.gz` / `-setup.exe` artifact.
- In a signed-in Web or Desktop session with a connected Computer, navigate to `/t/:tenantId/settings/models` (heading `Models`, `Model source`, `Local model` / `BYOK`).

## Driving it with Local Installer + Chromium (verify-local-client.sh)

Preconditions:

- Node `>=26.5.0 <27`, `pnpm@11.7.0`, Playwright Chromium, Go (from `apps/teamhub/go.mod`), and `python3` are available; `.claude/skills/verify/scripts/doctor.sh --local-client` exits `0`.
- No shared `~/.linger` home is targeted; every live run allocates a fresh temp `--home` directory under `${TMPDIR:-/tmp}/linger-verify-installer.XXXXXX`.
- Electron GUI, OS-installer upgrade, and real GPU weight-loading sub-features require a desktop display, installed Electron binary (`pnpm --filter @linger/desktop electron:install`), and supported Apple silicon Metal or NVIDIA CUDA hardware (see `Gotchas`).

- **Run the fast offline-safe isolated Local Installer proof (`installer-private-auth`, `installer-clean-stop`, BYOK SSRF API guard, Chromium SPA auth guard).** Run `.claude/skills/verify/scripts/verify-local-client.sh --smoke-only` (or `node .agents/skills/verify-linger/scripts/verify-local-client.mjs --smoke-only` on Windows). Builds `@linger/linger-installer`, starts `dist/installer.js` in a fresh temp `--home` on `--port 0`, verifies `700`/`600` modes on POSIX (Windows DACLs via `windows-private.native.test.ts`), confirms missing-`Origin` `POST /api/session` returns `403`, opens `<origin>/` in headless Chromium when Playwright Chromium is installed to verify the served React SPA renders the unauthenticated alert `Open the installer again.` with zero `pageerror`s (`installer-unauthenticated-guard.png` and `.aria.yml`), exchanges the one-time token (`200`, `HttpOnly; SameSite=Strict` cookie, and confirms `launch.html` is deleted from disk), confirms token replay returns `401`, checks authenticated `/api/environment`, `/api/config`, `/api/instances`, and `/api/jobs` return `200`, asserts `POST /api/byok/check` on `http://169.254.169.254/latest` returns HTTP `400 BYOK_INVALID_CONFIG`, stops the recorded PID, verifies headless `--stop` exits `0`, and removes the temp `--home`.
- **Run the authenticated Chromium `Choose your harness` + BYOK UI proof (`installer-ui-and-byok-ssrf`).** When external network downloads are allowed, run `.claude/skills/verify/scripts/verify-local-client.sh --smoke-only --with-setup-inspect`. Opens the bootstrap URL from `launch.html` in Chromium, waits for real `GET /api/setup` (`localmodels` tool download and hardware inspection) to display heading `Choose your harness` (`installer-choose-harness.png`/`.aria.yml`), selects radio `BYOK` in radiogroup `Installation plan`, fills `Base URL` (`http://169.254.169.254/latest`) and `Model` (`stub-model`), clicks `Test`, and verifies both HTTP `400 BYOK_INVALID_CONFIG` and visible toast `Couldn't connect` (`installer-byok-ssrf-refused.png`/`.aria.yml`).
- **Run the full host Local Client deterministic suites + live proof (`local-client-host-suites`).** Run `.claude/skills/verify/scripts/verify-local-client.sh` (or `node .agents/skills/verify-linger/scripts/verify-local-client.mjs` directly on Windows). Executes `@linger/service-kit` BYOK endpoint tests, `@linger/local-installation` (plus Windows native ACL/process tests on `win32`), `@linger/linger-installer`, `@linger/desktop`, Python Desktop packaging tests, Go Daemon `localmodels` / `model_source` tests, and the live Local Installer proof above; records non-host OS checks honestly under `skippedOs` in `<evidence-dir>/proof.json`.
- **Drive an already-installed Desktop sleep/wake/quit resilience check (`desktop-gui-and-models-surface`).** On a target host with an installed Desktop app that finished Quick Install with a local model, run `node .agents/skills/verify-linger/scripts/verify-sleep-quit.mjs --app-exe <linger-executable> --launch '<start-command>'`. Records per-phase JSON evidence for `baseline`, `freeze-all`, `freeze-daemon`, `run-across-freeze`, `engine-kill`, `quit`, `relaunch`, and `crash` under `test-results/verify-linger/sleep-quit.*/`.
- **Clean up and confirm proof.** Run `.claude/skills/verify/scripts/cleanup.sh <evidence-dir>` and verify zero recorded PIDs or temp homes remain while `<evidence-dir>/source.txt`, `<evidence-dir>/proof.json`, `<evidence-dir>/run.log`, and `<evidence-dir>/browser/installer-*.png` + `*.aria.yml` (when Chromium ran) are preserved.

## Gotchas

- Never pass `$HOME/.linger` as `--home` or leave `LINGER_DESKTOP_USER_DATA` unset when testing Desktop/Installer changes; doing so mutates the user's real installation and `doctor.sh --local-client` refuses `$HOME/.linger`.
- Never print or save the full `launch.html` URL or its one-time bootstrap token into logs, screenshots of raw HTML, or `proof.json`.
- Opening an authenticated Local Installer page triggers `GET /api/setup`, which runs `inspectSetup()` and downloads/verifies the ~4,700-file `localmodels` kit into a fresh `--home` over the network (often exceeding 20 seconds and failing in offline environments). Use `--smoke-only` for zero-external-network verification, and pass `--with-setup-inspect` only when network access is intended.
- Headless `--smoke-only` and full `verify-local-client.sh` runs do NOT prove packaged Electron GUI rendering, macOS `.dmg`/Windows `-setup.exe`/Linux `.tar.gz` upgrades from the previous release, multi-GB `localmodels` GPU weight downloads, or live external BYOK provider inference. If a task touches those paths without a target desktop/GPU host, report them explicitly as blocked with the missing hardware/OS precondition rather than weakening the claim.
- Settings -> Models (`/t/:tenantId/settings/models`) requires an enrolled online Computer (version `>= 0.56.0` for BYOK endpoint commands); on the isolated Web stack without a Computer, `/t/:tenantId/settings/models` shows the empty `No computers yet` state, which is expected there and does not prove model download or switching.
- For Desktop release candidates, the upgrade-from-previous-release journey on each shipped OS is mandatory; see [.agents/skills/verify-linger/features/desktop-and-installer.md](../../../../.agents/skills/verify-linger/features/desktop-and-installer.md#upgrade-from-the-previous-release).
