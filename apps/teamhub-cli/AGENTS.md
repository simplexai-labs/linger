# TeamHub CLI: standalone Agent business client

- Use `pnpm --filter @linger/teamhub-cli test`, `typecheck`, and `build` for this boundary.
- Keep the CLI independent of Agent Service, daemon, internal Runs, and MCP sessions.
- TeamHub owns authorization and transactions; local configuration only selects identity and business defaults.
- Call TeamHub through `client.api`, `openapi-fetch` typed by the generated `teamhub-agent-api` paths; `client.request` is only for byte transfers. A new endpoint goes into the contract first.
- The business zod schemas live in `src/domains`, and the host file helpers (exact reads, working copies, Skill packing) in `src/files`; nothing else consumes them, so they stay in this app.
- Keep help and schemas local and explicit that they do not grant permission. Common commands accept stdin in one shell invocation.
- Never discover a fresh Task input version when finishing old output. Capture immutable business revisions before work.
- Keep no local receipts, frozen input, send plans or locks. Every write carries one operation ID (`--operation-id` or a fresh one per invocation) and TeamHub deduplicates it; an unknown outcome prints the ID for a deliberate retry, and a connected-app write is never repeated by the CLI. Tracking Item writes are the exception: TeamHub deduplicates them by `idempotency_key` and `expected_revision`, so they offer no `--operation-id`.
- Working-copy records hold only the downloaded base of each path; TeamHub's CAS, not local state, protects concurrent work.
- Exclude private configuration, credentials and repository metadata from publication, including nested trees and symlink aliases.
- Human documentation belongs in `README.md`; `--schema` is projected at runtime from `commandDefinitions` and the tool zod, so there is no generated catalog to update.

## Errors

- Every failure is a `CliError` whose code is in the closed `ErrorCode` set of `src/errors.ts`: the CLI's own codes, TeamHub's declared `AgentApiErrorCode` values, and the few undeclared codes some TeamHub routes send. The type checker rejects a code outside the set; `src/error-codes.test.ts` checks that every code TeamHub declares has a template and an exit code.
- The CLI's general codes: `usage` (the command line is malformed: unknown command or flag, missing flag, positional count, flags that exclude each other), `invalid_input` (a value, JSON, schema, local file or size is wrong), `configuration_error`, `connection_failed` (nothing reached TeamHub), `outcome_unknown` (a write may have happened; it carries `operation_id` when TeamHub deduplicates by one) and `internal_error` (a CLI bug). Connector codes such as `account_ambiguous`, `target_ambiguous` and `authorization_required` keep their own cases.
- Exit codes come from `exitCodes` in `src/command-errors.ts`: 2 fix the input, 3 the current state conflicts, 4 not authorized or waiting for the user, 5 not found, 1 anything else. A code this build does not know exits by its HTTP status.
- Where a message comes from decides whether it is shown. A message the CLI wrote (`origin: "local"`) is shown as written, so write it for the caller. TeamHub's and providers' prose (`"remote"`) is never shown; the code's entry in `templates` replaces it. A new TeamHub code needs a template and an exit code, which the type checker requires once the contract is regenerated.
- Internal Inbox addresses, backend or provider prose, credentials and signed URLs never enter a message or `details`; only the listed `details` keys reach the output. A resource that is not permitted reads the same as one that does not exist.
- Report each problem as an issue `{path, code, message}` through the helpers in `src/input-issues.ts` (`invalidInput`, `invalidFlag`, `missingFlag`, `conflictingFlags`, `usageError`, `fileFailure`, `zodInputIssues`, `ajvInputIssues`). `path` is a flag, a field path inside a JSON flag, or `arguments`. `code` is one of `missing`, `unknown_field`, `invalid_type`, `invalid_value`, `out_of_range`, `invalid_format`, `conflict`, `invalid_json`, `unreadable` and `unwritable`, and its message follows that code's sentence, for example `required; use null if there is none.`, `must be an integer from 1 to 200; got 0.`, `give only one of --content, --file.`, `line 3, column 3: expected a property name in double quotes.` or `missing.md: not found.` Echoed values are cut at 40 characters, and secret fields are never echoed.
- The whole input is checked before configuration is read, so a caller without a configured Context still learns every field to fix.
- A tool schema's text bound counts Unicode characters, the unit the contract's `maxLength` states: `codePointString` publishes `maxLength` from the same number and repeats it as a refinement, because a refinement alone never reaches the schema.
